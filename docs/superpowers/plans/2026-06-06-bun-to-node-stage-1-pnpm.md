# Bun → Node Migration: Stage 1 — pnpm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Bun's package manager + workspace runner with pnpm 9. Bun still executes all code (test runner, build scripts, dev/start). End state: `pnpm install` bootstraps the repo, `pnpm -r X` orchestrates workspace commands, `bun.lock` is gone, `pnpm-lock.yaml` is the source of truth.

**Architecture:** Add pnpm via Corepack, generate a fresh `pnpm-lock.yaml`, mechanically rewrite every `bun --filter`/`bun x` script invocation across 12 `package.json` files, 7 CI workflows, husky hooks, Dockerfile, and the PR template. Add `"node": ">=22"` to root `engines` so Stage 2 can add a Node CI matrix entry. Bun stays as the runtime executing `bun test` and `bun run scripts/*` — pnpm orchestrates, Bun executes.

**Tech Stack:** pnpm 9 (via `packageManager` field + Corepack), workspace protocol unchanged (both pnpm and Bun accept `"workspace:*"`), Node 22 declared in `engines`, Bun 1.3.11 still required at this stage.

## Task 7: Update Dockerfile to layer pnpm via Corepack

**Files:**
- Modify: `Dockerfile`

- [ ] **Step 1: Add Corepack pnpm activation to the `deps` stage**

Locate the `deps` stage near the top of the Dockerfile:
```dockerfile
FROM oven/bun:1.3.11-slim AS deps

```

Change to:
```dockerfile
FROM oven/bun:1.3.11-slim AS deps

WORKDIR /app

# Enable pnpm via Corepack. Node ships with Corepack since 16.10, but the
# oven/bun base image doesn't include Node — install it first.
RUN apt-get update && apt-get install -y --no-install-recommends curl ca-certificates \
 && curl -fsSL https://deb.nodesource.com/setup_22.x | bash - \
 && apt-get install -y --no-install-recommends nodejs \
 && rm -rf /var/lib/apt/lists/* \
 && corepack enable \
 && corepack prepare pnpm@9.15.0 --activate

# Copy root package files and lockfile
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml ./
```

- [ ] **Step 2: Replace the `bun install` line with `pnpm install`**

Locate:
```dockerfile
# Install ALL dependencies (including devDependencies needed for web build)
# --linker=hoisted: Bun's default "isolated" linker stores packages in
# node_modules/.bun/ with symlinks that Vite/Rollup cannot resolve during
# production builds. Hoisted layout gives classic flat node_modules.
RUN bun install --frozen-lockfile --linker=hoisted
```

Change to:
```dockerfile
# Install ALL dependencies (including devDependencies needed for web build).
# --shamefully-hoist gives a flat node_modules layout that Vite/Rollup can resolve
# during production builds — equivalent purpose to Bun's --linker=hoisted.
RUN pnpm install --frozen-lockfile --shamefully-hoist
```

## Self-review notes (for the executing agent)

- This stage adds **no new functionality** and changes **no runtime behavior**. Every script that worked under Bun still runs under Bun; pnpm just orchestrates the invocations.
- The migration is fully reversible at any task with `git revert`.
- Watch out for: peer-dependency warnings during `pnpm install` (pnpm is stricter than Bun about peers). If any warning is non-benign, capture it in `pnpm.peerDependencyRules` rather than ignoring it.
- Watch out for: `--linker=hoisted` (Bun) vs `--shamefully-hoist` (pnpm) in Dockerfile. Both produce flat `node_modules` for Vite/Rollup compatibility; the flag is renamed but semantically equivalent.
- The `bun run scripts/*.ts` invocations in root `package.json` (`generate:bundled`, `check:bundled`, etc.) are **intentionally** left as `bun run` in this stage — they're swapped to `tsx` in Stage 4 along with the dev runtime swap.
